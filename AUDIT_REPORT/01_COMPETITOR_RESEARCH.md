# Competitor Research

Research date: 2026-11-25. Sources are primary repositories and official docs linked in 22. Branches are mutable; the reachable GitHub commit-history pages exposed historical short SHAs from September 2026, not a verified November tip. Do not treat these as exact audit-date checkouts.

## OpenCode

Repository: [anomalyco/opencode](https://github.com/anomalyco/opencode), branch `dev`. It is an integrated open-source coding agent with terminal, desktop/web/IDE surfaces and a server/client architecture. The repository's `packages/` and `services/` split product surfaces and shared runtime; official docs expose configuration for providers, agents, tools, MCP, plugins, sessions and permissions. Tool policies support allow/ask/deny and wildcard scopes; tool execution can use Code Mode, where JavaScript composes catalog tools but has no direct filesystem or import/timer access. Denying Code Mode does not itself deny nested tools, so permissions still apply at the leaf. ACP provides an integration protocol and lifecycle for session creation/loading/forking, command updates, permission prompts and MCP transport. These are documented and source-visible capabilities; this audit did not build/run OpenCode.

Strength: integrated and policy-aware tool/session UX; extension points do not depend on one monolithic chat view. Tradeoff: more product and configuration complexity; runtime breadth raises maintenance and security-review costs. Relevant primary evidence: [tools docs](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/tools.mdx), [agents docs](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/agents.mdx), [MCP docs](https://github.com/anomalyco/opencode/blob/dev/packages/web/src/content/docs/mcp-servers.mdx), [ACP docs](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/cli/acp.mdx).

## Pi Coding Agent

The requested URL redirects to the canonical [earendil-works/pi](https://github.com/earendil-works/pi) repository (formerly `badlogic/pi-mono`). Pi calls itself a minimal extensible harness. It is organized as packages for unified LLM API, agent core, coding agent, and terminal UI, plus extensions/examples. The coding agent supports interactive, print/JSON, RPC and embeddable SDK modes; extensions can add tools, commands, UI, hooks, providers and custom rendering. Docs describe session branching/tree navigation, compaction, context files, skills, prompt templates, model switching, message steering/follow-ups and cancellation. The smaller core invites user-defined workflows instead of prescribing a large product. Extension APIs are powerful code execution and should be treated as trusted code; extension presence is not equivalent to sandboxing.

Strength: clear seams and broad customization with a usable standalone coding workflow. Tradeoff: fewer integrated out-of-box workstation surfaces than Abyx; ecosystem behavior may depend on extensions. Evidence: [Pi README](https://github.com/earendil-works/pi), [coding agent README](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/README.md), [extension docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md), [skills docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md).

## DeepSeek Harness (DSH)

The exact harness exists publicly at [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness), plus the official [Harness site](https://www.deepseek.com/harness/en/). It is distinct from DeepSeek model quality and API support. Its stated design centers Cordis: plugins provide services/events/effects in a context, with profile/bundle layering and a web/headless/desktop runtime. Source/docs span `packages`, `apps`, `native`, `python`, `docs`, `benchmarks`, and vendor code. The DSH documentation describes the agent loop, model adapter, tool registry, session log and UI as composable plugins. Its MCP client namespaces remote tools, supports stdio/HTTP, cancellation and reconnection; startup failures can leave optional servers unavailable. The product offers a desktop app and web UI, and the project discusses experimental agent teams. Experimental/documented behavior must not be represented as verified production reliability.

Strength: architecture-level replaceability and explicit plugin lifecycle, profiles, and distribution. Tradeoff: composition adds startup-order, dependency, and lifecycle complexity; plugins run trusted code. Abyx's `harness/` echoes the concept but has a small hand-built EventEmitter registry, not Cordis-compatible DSH. Evidence: [DSH repo](https://github.com/deepseek-ai/deepseek-harness), [architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md), [MCP client docs](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md), [official site](https://www.deepseek.com/harness/en/).

## Comparative judgment

OpenCode is the strongest reference for integrated coding UX and explicit policy/session APIs; Pi for a compact embeddable loop and ergonomic runtime extension surface; DSH for plugin/profile composition and deployable harness layers. Abyx has a wider local media/model workstation scope. Adopt principles, not wholesale feature checklists. No competitor performance claim was benchmarked in this audit.
