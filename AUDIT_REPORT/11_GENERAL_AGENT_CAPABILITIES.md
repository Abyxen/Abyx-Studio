# General Agent Capabilities

Abyx extends beyond code through browser/search (`services/browser_service.js`), research skills, document/PDF generation (`services/universal_file_generator.js`, `scripts/pdf_builder.py`), study workflows, audio transcription, text-to-speech, image/video generation, automation, Obsidian sync, subagents and MCP. These are meaningful differentiators against coding-first OpenCode and Pi. Their presence is split between route modules, frontend panels, local worker scripts and third-party provider calls, so a feature inventory should distinguish available UI from installed model/runtime, configured credentials and successful operation.

No browser automation reliability, document extraction accuracy, long-running automation recovery, or agent-team execution benchmark was performed. The browser tool's timeout signal is not passed through in `fetchPage`; public fetch security should be centrally enforced. Automation is persisted JSON and multiple service interactions need durable job IDs, retry policy, permission boundaries and cancellation. Subagent personas are not evidence of isolated workspaces/context or coordinated task scheduling.

Recommended common workflow abstraction: typed job with inputs, selected provider/model, requested capabilities, approvals, checkpoints, events and artifacts. Feature plugins should request capabilities rather than importing broad services. Run long jobs as cancellable managed processes with explicit state, resource budget, logs and clean shutdown. For general-purpose tools, treat fetched pages/documents as untrusted data and maintain source citations and user-visible provenance. See 16–18 for the architecture and validation plan.
