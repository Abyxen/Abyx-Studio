# AI Studio Capabilities

Abyx's broad studio scope includes model catalog/download/import/start/stop and benchmarks, local backends, cloud-provider credentials/routing, usage analytics/budgets, generated media, speech/TTS, workspaces, automations and agent settings. UI entry points include `ModelManager.jsx`, `CloudProviders.jsx`, `UsageDashboard.jsx`, `Generator.jsx`, `SpeechTranscriber.jsx`, `TextToSpeech.jsx`, `VideoGenerator.jsx`, `AutomationsManager.jsx`, and `HarnessManager.jsx`. Server-side process management is split among `services/process_lifecycle_manager.js` (untracked at audit start), `services/model_manager_service.js`, `services/silent_process.js`, workers and large server routes.

This breadth is a product strength but multiplies runtime failure modes: model downloads and child processes consume disk/GPU; dependencies may be absent; providers may rate-limit; workers may hang; status may drift from process reality. `app/config/abyx-processes.json` and `services/process_lifecycle_manager.js` were pre-existing untracked changes at audit start and are part of current tree, not attributed to HEAD. No GPU/CPU/memory/startup measurements were taken.

Recommend one process supervisor contract with role, PID ownership, health probe, heartbeat, cancel/kill-tree, resource limit, redacted logs and shutdown drain. Keep each modality optional and isolate its availability state from chat/agent health. Model catalog should include source, quantization, context, license, hardware needs, checksum and running state. Benchmarks need warm/cold timing and repeat counts. Avoid making multimedia features depend on the coding-agent runtime when they can remain optional services.
