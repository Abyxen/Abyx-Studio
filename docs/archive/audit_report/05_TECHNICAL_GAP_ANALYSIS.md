# Technical Gap Analysis

Priority P0–P4; complexity LOW/MEDIUM/HIGH/VERY HIGH. All findings are static; risk describes plausible impact, not an exploited vulnerability.

| ID | Finding and Abyx evidence | Priority / complexity / risk | Recommendation and dependency |
|---|---|---|---|
| G-01 | Safe shell regexes in `agent/policy_engine.js` are prefix matches; e.g. a read-only Git prefix can contain subsequent shell commands. `terminal_tool.js` invokes `exec`, so shell metacharacters are meaningful. | P0 / HIGH / critical command execution | Replace regex classification with parsed, allowlisted executable+argument policy; default ask/deny for unknown. For broad shell support, require OS sandbox. Add adversarial policy tests before enabling. |
| G-02 | `agent/path_guard.js` validates only immediate parent for missing targets; a nested missing parent can have an unchecked symlink ancestor. Separate check/write creates race windows. | P0 / HIGH / data escape | Resolve nearest existing ancestor and verify every existing path segment; use handle-based/no-follow operations or isolated workspace filesystem; revalidate before mutation. |
| G-03 | `provider_sandbox.js` uses Node `vm` and Python process. VM has no OS boundary; subprocess inherits user privileges. Terminal cwd pinning also does not restrict commands' file/network access. | P0 / VERY HIGH / host compromise | Document trust boundary honestly; implement OS-level disposable sandbox (container/VM/job object + seccomp/AppContainer where available), resource caps, network policy, read-only mounts. Depends on platform design. |
| G-04 | `harness/agent_seam.js` direct `consumerTools.executeTool()` bypasses `PolicyEngine`; the main route instead calls `AgentExecutionEngine`. | P1 / HIGH / policy bypass | Remove duplicate dispatch or route every tool call through the canonical authorization/execution interface. Runtime registry should expose only approved ToolExecutor. |
| G-05 | `buildStepExecutor` tests `activeRun.stepsExecuted === 0`, but `AgentExecutionEngine.run()` increments it before calling executor. Folder/PDF shortcuts are unreachable. | P1 / LOW / broken user workflow | Test against `step.stepNumber === 1` or move trigger logic; tests for supported user phrases and refusal cases. |
| G-06 | `/api/agent/stream` uses `req.on("close")` to abort; request completion and response disconnect are distinct lifecycle signals. Browser fetch cancellation may therefore be unreliable. `ControlledBrowserTool.fetchPage` creates combined signal but omits it from `fetchPublicResponse` options. | P1 / MEDIUM / stuck work or unbounded wait | Bind cancellation to response/socket disconnect correctly; pass signal through resolver/request/read; test disconnect, timeout and cleanup. |
| G-07 | `context_manager.js` estimates tokens by chars/word blend and compacts older turns to a few first-line prompts. It can discard assistant/tool state and uses static model limits. Agent prompt does not apply compaction. | P1 / MEDIUM / context loss | Use provider/tokenizer-aware counts when available; compact typed messages and tool pairs; preserve instructions and recent task state; integrate with runtime and report approximation. |
| G-08 | SQLite chat, run JSON and `HarnessSessionStore` JSON are distinct. Session JSON is synchronously reread/rewritten per event, with no locking/atomic commit; cancellation/restart recovery is unclear. | P1 / HIGH / lost/corrupt history | Canonical append-only event/session store, atomic snapshots, schema versioning, resumable run state and stable ownership keys. |
| G-09 | `providers/registry.js`, adapters and `ai_providers.js` contain multiple model discovery/routing layers; agent path expects `resObj.content` and arbitrary chunk shapes. | P1 / HIGH / wrong route/stream failures | Define provider contract for capabilities, limits, tool support, structured errors, stream events, retries and cancellation. Contract tests per adapter. |
| G-10 | `extensions/plugin_runner.js` `require()`s installed extension entry in process. Manifest validation does not isolate code side effects. | P1 / HIGH / local data/code exposure | Treat extension installation as code execution: signed provenance, review/trust prompt, least-privilege capability API and process isolation. Maintain explicit permission lifecycle. |
| G-11 | MCP configuration/dispatch in `services/mcp_client.js` feeds consumer tools; policy semantics and connection startup/reconnect/error state are not shown as one lifecycle. | P1 / HIGH / remote tool misuse | Server-qualified stable IDs, per-tool schema validation, per-server approval rules, timeouts/cancellation, reconnect state, secret vault and audit correlation. |
| G-12 | Agent-native registry has no Git operations; `PathGuard` blocks `.git`. Terminal-based Git is unstructured and subject to G-01. | P2 / HIGH / weak code editing/recovery | Add read-only status/diff first, then approval-bound patch/commit operations; preserve user changes and avoid automatic destructive Git. |
| G-13 | Run/timeline logging exists, but multiple session stores and per-tool events have limited common correlation/retention/redaction policy. | P2 / MEDIUM / hard incident diagnosis | Stable request/run/session/tool IDs, bounded structured logs, telemetry consent and documented retention. |
| G-14 | Interface has many screens, but tests and accessibility/runtime evaluation were not run; agent activity view combines status and execution actions. | P2 / MEDIUM / user confusion | Usability and keyboard/accessibility pass against actual screenshots; separate run timeline, approval queue, diff and recovery states. |
| G-15 | RAG parser/chunker/embedding/retrieval components exist; no benchmark validates recall, citation correctness, stale-index behavior or injection resilience. | P2 / HIGH / incorrect answers | Add ingestion/index lifecycle, source provenance, retrieval eval set, filtering and delete/re-index contracts. |
| G-16 | AI studio model/media workers and automations are broad but rely on subprocesses/providers with differing state/observability. | P2 / MEDIUM / resource leaks | Shared lifecycle manager, limits, health states and workflow cancellation; keep modality services optional. |

### Additional concrete observations

- `createAgentEngine()` defaults terminal off, but `getAgentRuntime()` explicitly enables it. The route then uses PolicyEngine, but policy is only as reliable as its command classifier.
- `PathGuard` blocks `.git`, so a future structured Git integration must use a separately designed, narrow internal repository API rather than weakening sensitive-path rules wholesale.
- The README's “safe sandbox” and production-ready language exceeds the verified static guarantees. Documentation should describe the actual host-user trust model until OS isolation exists.
- No observed benchmark results justify performance comparisons. See 18.
